**3. 示波器最终优化 —— ★ 2026-10-03 软件部分做完（HDL 部分待板子）**
```
★★★ 最重要的发现：「EQ / ADC 接线」的真相
────────────────────────────────────────────────────────────────
BD（system.bd）里的连线是这样的：

    "scope_tie_dout1": {
      "ports": [ "scope_tie/dout",     ← 一个 xlconstant
                 "scope_0/adc_data" ]  ← 接到示波器的外部 ADC 输入
    }
    而 scope_tie 的参数：CONST_VAL = "0"   CONST_WIDTH = "8"

⇒ 就是接了个【8 位常量 0】。

⇒ 所以「源: ADC」模式读到的永远是 0 —— 这不是"没调好"，
  是物理上根本没有信号进去。测波形永远是平的。

要真正修，必须改 BD（把 adc_data 接到真实信号源）+ 重新出流 + 刷板。
候选信号源：
  · i2s_receiver 的音频数据（BD 里已有，但 48 kHz vs 20 MSPS 差 400 倍）
  · ★ 好消息：见下面"时基表"——慢采样硬件本来就支持，
    DIV=2000 时 adc_clk = 50 kHz，DIV=2083 正好 48 kHz
  · 或者接 PL 内部某个信号（当逻辑分析仪用）

★ 所以这一步【留到接音频那条线一起做】，不要单独改 BD。

────────────────────────────────────────────────────────────────
★ 软件部分（已完成，纯 Python，不用刷板）
────────────────────────────────────────────────────────────────

① auto_set() 重写
   老版三行，问题很实际：
     · 触发电平硬编码 128 —— 信号若只在 0~100 摆动，永远够不着
     · 只按当前时基测一次 —— 测不到频率就放弃
     · 不看信号强弱 —— 可能把噪声当信号，"自动设置完成"却什么都没
   新版照真实示波器：
     · 【扫】一遍时基，边沿数 2~40 的那档最合适
     · 触发电平用实测中点 (min+max)/2
     · 按占空比选边沿（窄脉冲用上升沿更稳）
     · 真没信号就明说"没检测到信号（摆幅 < 3 LSB）"，不假装成功
     · ★ tie-break：多档边沿数相同时，偏好窗口 1ms~50ms 的档
       （实测缺这个会挑到 50ns/点，1kHz 信号只显示 0.2 个周期）

② ★ 解开一个循环依赖
   apply() 原来是"随时基算 DDS 频率"，让窗口里永远 20 个周期：
       span = 4096 * div*dec / 100MHz
       want = 20.0 / span
   看着讨喜，但副作用致命：**DDS 频率跟着时基跑**
   ⇒ 「自动设置」就没意义了（挑哪档都是 20 个周期，测出的频率也跟着变）
   ⇒ 而且真实信号不会随时基变，DDS 这样自检也没意义
   现在：频率【固定】，加了「频率 -/+」按钮（19 档，1Hz~800kHz，
         1-2-5 序列）。时基一变，屏幕上的周期数就变 —— 和真实信号一致。

③ ★ 时基表从 10 档扩到 23 档（也是纯 Python 收益）
   查 HDL 时发现：div 是【16 位】、dec 是【8 位】，
   硬件只限制 div >= 4（div_ok = div < 4 ? 4 : div）
   ⇒ 最慢 = 65535 * 255 / 100MHz = 167 ms/点，窗口 11 分钟！
   ⇒ 慢采样【PL 层面一直就支持】，只是 Python 没给档位。

      改前：10 档，窗口 205us ~ 52ms（只能看 19 Hz 以上）
      改后：23 档，窗口 205us ~ 11.4 分钟（0.0015 Hz 也能看完整周期）

   ★ 附带：adc_clk = 100MHz / DIV，所以 DIV=2000 时是 50 kHz、
     DIV=2083 正好 48 kHz —— 将来接音频时，时基表里直接有匹配档。

★ 离线测试（没有板子，走 scope.py 的仿真分支）：
   · 正常信号 -> 触发电平按中点算（120，不是硬编码 128）✓
   · 全 0 / 摆幅 1 LSB -> 正确报"没检测到信号" ✓
   · sim 1kHz 信号 -> 自动挑到 2.5us/点 = 窗口 10 个周期 ✓
   · 23 档时基表的窗口宽度逐档核算过 ✓

★ 待部署（板子开机后）：
   ui/scope.py、ui/apps_scope.py -> /home/zynq/ui/ + 重启 zynq-desktop
   ★ 板上验证：自动设置按钮、频率 -/+、慢档时基
```

★★★ 流式怎么做的
────────────────────────────────────────────────────────────────
第 1 步【快照重识别】（已经有）：按下开始录音，每 1.2 秒向音频服务

    1.2s -> "现在几点了？"            1.1 秒
    2.4s -> "现在几点了？帮我看看。"   0.6 秒
总耗时 2.2 秒（音频本身 2.89 秒）—— 比音频还快。

第 2 步【VAD 句子切分】（今晚加的）：
  短句没问题，但长句会塌 —— 每次送"从头到现在"的整段，
  说到 20 秒时每次要传 ~640KB，百度要 2~3 秒才回，越说越滞后
  （而且百度短语音上限 60 秒）。
  ⇒ 用静音把话切成句：后面跟着足够长静音的句子【定稿】，
     只识别一次、缓存住；只有最后那句每轮重识别。
     每句都短 ⇒ 又快又准，说多久都不拖慢。

  ★ 手写而不用现成库的原因：
      · 板子【没有 numpy】（1GB 内存，不想为这个装）
      · PC 上【没有 audioop】（Python 3.13 已按 PEP 594 移除）—— 踩到过
    ⇒ struct 解 int16 + 自己算 RMS，20ms 一帧。

  VAD 实测（合成音频 5.13s = 第一句 2.01s + 静音 0.8s + 第二句 2.32s）：
      找到的句边界: [2.08, 4.70]
      ★ 2.08 正是第一句结束的位置（期望 2.05）✓

第 3 步【静音过滤】—— 又是一个真 bug：
  VAD 把 2.46 秒切成边界后：
      定稿段 [0, 2.46)    -> "现在几点了？帮我看看。"   ← 对
      当前段 [2.46, 末尾) -> "我知道。"                ← ★ 凭空多出来的
  尾部那 0.4 秒是【纯静音】，而百度对静音会**幻觉**出文字。
  ⇒ 送 ASR 之前先量 RMS，低于阈值就不送。
    阈值 100（实测真实说话 RMS 800~3000，板子底噪 <50，分得很开）。
    ★ 边界照样推进，否则下一轮会重复处理同一段。

第 4 步【超长保护】—— 第三个真 bug：
  如果一轮识别要好几秒（网络慢 / 第一次取 access_token），
  录音会在这期间继续累积 ⇒ 快照很快涨到几十秒 ⇒ 每轮要传几百 KB、
  百度要 30~50 秒才回 ⇒ **越说越慢，滚雪球**。
  实测一次 6 轮的测试：音频 2.0s -> 10.5s -> 25.9s -> 57.5s。
  ⇒ 两条保护：当前句 > 18 秒就把前一半强制定稿；
     并把快照总长夹在百度上限内。

★★ 反馈①「稍微长一点就不对」—— 根因是静音阈值太小
────────────────────────────────────────────────────────────────
排查过程（一步步排除，值得记）：
  · 先在板子上用 TTS 生成 2.0s / 3.9s / 7.9s 三段已知语音，对比
    【整段识别】和【VAD 分句识别】—— 结果完全一致且全对
    ⇒ 说明分句逻辑本身没错
  · 再隔离重采样：16000 → 升到 44100 → 用 audioop.ratecv 降回 16000
    对比原始 16k。三种方式（原始 / audioop / 加低通）结果【完全一致】
    ⇒ 重采样也不是问题
  · 还确认了硬件真实采样率（arecord 5 秒实测 44100.0 Hz，差 0.0%）

★ 那问题在哪？看这三段 TTS 音频的共同点：**中间没有停顿**，
  所以 VAD 只切出结尾一个边界，等于没切 —— 和"整段识别"没区别。
  而【真人说话不一样】：长句里全是自然停顿（呼吸、思考、"嗯…"）。

★ 根因：MIN_SIL_SEC 原来是 0.45 秒，会把
      "帮我看看 / 今天天气 / 怎么样" 切成三段，
      每段单独送百度 ⇒ **失去上下文** ⇒ 长句开始出错。
      短句没这个风险 ⇒ 正好对应"短的对、稍微长一点就不对"。

⇒ 修法两条：
   ① MIN_SIL_SEC  0.45 → 0.85 秒（只在真的说完了的地方才切）
   ② slice_wav() 加 ctx 参数，定稿段前后各多带 0.35 秒上下文
      （切在静音中间虽不会切到词，但语气词/连读要靠上下文才认得对）

    case1 2.01s  A/B 一致 ✓ 「现在几点了？」
    case2 3.90s  A/B 一致 ✓ 「帮我看看今天北京的天气怎么样？」

★★ 顺带查到的硬件事实（以后有用）
────────────────────────────────────────────────────────────────
· ES8388 的 0x0A 寄存器选 ADC 输入：
      0x00 = LIN1/RIN1 = 板载麦克风   ★ 要的是这个
      0x50 = LIN2/RIN2 = LINE_IN 插孔（厂家默认）
  ★ 实测遇到过它变回 0x50 的情况（那样录到的就是没插线的插孔）。
  现在确认是 0x00。以后"录音没声音"先查这个寄存器。

· 这块板子的音频链路是【全用户态 PL 驱动】：

· 麦克风电平实测：底噪约 -57 dBFS（安静房间）。
