## 2. 板端部署

### 2.1 对板子的要求

| 项 | 要求 |
|---|---|
| 型号 | 正点原子 领航者 ZYNQ7020（xc7z020clg400-2） |
| 系统 | Ubuntu 20.04 armv7l，内核 `5.4.0-xilinx-v2020.2`（现役板子就是这个） |
| Python | 3.8.10（★ 不要换 3.13：`audioop` 被移除了，音频服务会直接崩） |
| 内存 | 1 GB（够用，但别在上面跑编译） |
| SSH | 用户 `zynq` / 密码 `123456`，`sudo -n` 免密 |
| 屏幕 | 1024×600 framebuffer（`/dev/fb0`，24bpp，stride 3072） |
| 触摸 | `/dev/input/event1`（Goodix 电容屏） |
| SD 卡 | ≥ 16 GB，分两个区：`mmcblk0p1`(256M, FAT, 挂 /mnt/boot) + `mmcblk0p2`(ext4, 根) |

### 2.2 跑部署脚本

```bash
# 把整个交接包拷到板子上（scp / U 盘都行），然后：
cd 交接包
sudo bash 板端部署.sh --dry-run    # ★ 先空跑一遍，看它打算做什么
sudo bash 板端部署.sh              # 真部署
```

脚本是**幂等**的，重复跑不会炸；覆盖已有配置前会自动备份成 `.bak_<时间戳>`（权限 0600）。

它做 9 步：检查环境 → 建目录 → 拷 `board_*` → 装 `/etc` 配置 → 装 systemd unit
→ 配 ES8388 麦克风 → 重启服务 → 打印状态。

### 2.3 部署后自查

```bash
# 八个服务应该都是 active
for s in zynq-desktop zynq-agent zynq-audio cloud-api thermal-guard thermal-cooldown \
         zynq-screen-guard zynq-gpu-loader; do
  printf "%-22s %s\n" "$s" "$(systemctl is-active $s)"
done

# ★ 麦克风关键寄存器：必须是 0x00（板载麦 LIN1/RIN1）
sudo i2cget -f -y 1 0x10 0x0a
#   0x00 = 对    0x50 = 错（接了 LINE_IN 插孔，没插线 ⇒ 录到的近乎全静音 -93dBFS）

# 硬件自检
sudo python3 /home/zynq/agent/hw_change.py verify   # 或走 agent 的 hw_verify 工具
```

## 4. FPGA

### 4.1 刷一个现成的 bitstream

现役板子跑的 `board_boot/system.bit`（4,045,769 字节，md5 `369b1a18…`）就是能用的那一版。
它的改动：`gpu2d_axi.v` 里读未定义寄存器时返回 `0x47505532`（ASCII "GPU2"）而不是 `0xDEADBEEF`
—— 用来验证"新流真的生效了"。

```bash
sudo mount /dev/mmcblk0p1 /mnt/boot
sudo cp /mnt/boot/system.bit /mnt/boot/system.bit.bak_$(date +%s)   # 先备份
sudo cp 新流.bit /mnt/boot/system.bit
sudo sync && sudo umount /mnt/boot
sudo systemctl reboot        # ★ 只允许 reboot，绝不要 poweroff（见 §9 第 10 条）
```

### 4.2 重新出流

Vivado 工程不在这个包里（太大）。要重建的话：

```bat
:: 需要 Vivado 2026.1，工程在 D:\ubuntu_iso\atk2026\Navigator_7020\Navigator_7020.xpr
call D:\Xilinx\2026.1\Vivado\settings64.bat
vivado -mode batch -source fpga\build_cnn.tcl -log build.log
```

**★★ 改自研 IP 时有个必知的坑**（我们为此白跑过 25 分钟）：
`update_ip_catalog -rebuild` + `generate_target all` **不会**把 `gpu_ip/src/*.v` 的改动
传到工程里。综合真正吃的是 `.gen/sources_1/bd/system/ipshared/<hash>/src/*.v`。
- 改 IP 源码后要么**重新打包 IP**，要么**直接改 ipshared 那份**（实测 `generate_target` 不会覆盖它）
- 验证办法：`fpga/test_ip_propagate.tcl` 只跑目录刷新（约 20 秒），跑完比对 ipshared 里那行值
  —— 别等 25 分钟出流完才发现改动没生效

### 4.3 自研 IP 说明

| IP | 地址 | 作用 |
|---|---|---|
| `scope_cap_axi` | `0x43CC0000` | 数字示波器采集核心（4096 点 8bit 双 bank 环形缓冲，读 `+0x34` 得 `0x53434F50` "SCOP"） |
| `gpu2d_axi` | `0x43CB0000` | 2D 图形加速（读 `+0x34` 得 `0x47505532` "GPU2"） |
| CNN (HLS) | `0x43CD0000` / `0x43CE0000` | 卷积 + 全连接，做波形分类推理 |

## 5. ★ 密钥配置（不做这步，AI 功能全废）

`board_etc/` 里的文件是**脱敏模板**（值都换成了 `<你的值>`），部署时会装到 `/etc/`，
但**必须自己填真实值**。

```bash
sudo nano /etc/zynq-baidu.env        # 语音：ASR + TTS
sudo nano /etc/zynq-baidu-ocr.env    # 文字识别：手写 OCR
sudo nano /etc/xiaobai-cloud.json    # 云协同入口的 token
sudo systemctl restart zynq-agent zynq-desktop zynq-audio
```

### ★★ 两个容易卡住的地方

1. **百度智能云的「语音技术」和「文字识别」是两个独立应用**，各有一对 Key。
   在语音应用上勾「文字识别」是**勾不上的** —— OCR 接口会一直返回 `error_code 6 (No permission)`。
   ⇒ 要去文字识别控制台**另建一个应用**，勾「手写文字识别」，把那对 Key 放进 `zynq-baidu-ocr.env`。
2. **密钥文件权限是 `600 root`**（`-rw-------`），只有 root 能读。
   而桌面 App 跑在 `zynq-desktop` 服务里（该服务 `User=` 为空 = **root**）✓。
   ⇒ 如果哪天把桌面服务改成普通用户跑，语音识别会静默退回离线 vosk（识别率很差），
   **因为读不到密钥**。代码里已经做了「主动读这个文件」的兜底（`agent/tts.py` 的 `_load_env_files`），
   但权限本身还是要对。

### 硬件相关的关键事实

- **音频链路是全用户态 PL 驱动**：`ES8388 ADC → AXI I2S 接收器(0x43C60000) → audio formatter → DDR`。
  `audio_alsa_svc.py` 不碰 PL 寄存器，靠 `zynq-audio` 的 `ExecStartPre` 跑 `audio_cap_init.py` 来配。
  **★ 但 `board_units/zynq-audio.service.d/alsa.conf` 会把 ExecStart 覆盖成 `audio_alsa_svc.py`**
  —— 改主 unit 里的 `audio_svc.py` 是无效的，要改 drop-in。
- **`zynq-agent` 绑的是 `0.0.0.0:8765`**（局域网可直连，不是只听 127.0.0.1）。
- 温度：空载 65~88°C。**散热片要装**，`thermal-guard` 会在过热时降频/报警。

## 7. ★ 隐私：这个包里【不含】什么

**用户的对话记录和语音样本一律没有打包。** 具体排除（详见 `板端文件清单.md` §8）：

| 类别 | 路径 |
|---|---|
| 对话记录 | `.agent_chats.json`、`.agent_chats.json.lock`、`agent_sessions/`、`agent_spill/` |
| 语音样本 | `received/`（里面是用户的录音测试文件） |
| 阅读进度 | `.novel_marks.json`、`.novel_pos.json`、`.novel_pos` |
| 作息/天气缓存 | `.weather.json` |
| 个人文件 | `Books/`、`Music/`、`Pictures/`、`Documents/`、`ai_delivery/` |
| Shell 历史 | `.bash_history` |
| 凭据/配置 | `.ssh/`、`.config/`、`.cache/`、`.minetest/` |
| 可能含对话的日志 | `/var/log/` 下 6 个日志 |

另外 `board_etc/` 里的密钥是**脱敏模板**（`<你的值>`），原始密钥没有带出来。

**部署脚本还有一层纵深防御**：内置 `is_private()` 检查，即使将来有人误把对话文件塞进包里，
脚本也会**拒绝部署并告警**，不会把用户的对话带到新板子上。

## 8. 排障（按这个顺序查）

```bash
# ① 服务活着吗
systemctl is-active zynq-desktop zynq-agent zynq-audio cloud-api

# ② 桌面 App 报错了吗（★ 最有用的一条）
sudo tail -40 /var/log/zynq-desktop.log        # 搜 "APP ERROR"
sudo journalctl -u zynq-desktop -n 50 --no-pager

# ③ agent 通吗
curl -s http://127.0.0.1:8765/health

# ④ 麦克风有声音吗（RMS < 50 就是没拾到）
sudo python3 /home/zynq/audio_cap_init.py --check    # 看 0x0A 是不是 0x00
sudo python3 /home/zynq/audio_cap_init.py --test     # 录 2 秒看 dBFS

# ⑤ 硬件寄存器对不对
sudo python3 -c "
import mmap,os,struct
def rd(a):
    b=a&~4095; o=a-b
    fd=os.open('/dev/mem',os.O_RDONLY|os.O_SYNC)
    m=mmap.mmap(fd,4096,mmap.MAP_SHARED,mmap.PROT_READ,offset=b)
    try: return struct.unpack('<I',m[o:o+4])[0]
    finally: m.close(); os.close(fd)
print('scope_0 +0x34 = 0x%08X (期望 0x53434F50)' % rd(0x43CC0000+0x34))
print('gpu_0   +0x34 = 0x%08X (期望 0x47505532)' % rd(0x43CB0000+0x34))
"
```

### 常见症状 → 原因

| 症状 | 八成是这个 |
|---|---|
| 桌面全黑 / 只有壁纸 | `zynq-desktop` 挂了，看 `/var/log/zynq-desktop.log` 的 `APP ERROR` |
| 语音识别出来全是乱词 | ① 密钥没填/读不到（退回 vosk）② ES8388 `0x0A` 不是 `0x00` |
| 录音全是静音（RMS<50） | ES8388 `0x0A=0x50`，或 `audio_cap_init.py` 没跑 |
| 板子连不上 | IP 变了（DHCP）。`python board.py --find` 或在客户端设置里重新扫描 |
| 手写特别卡 | 老版本每帧整屏 flush。现版本改成了脏矩形 blit（快 75 倍），确认用的是包里的 `input_panel.py` |
| exe 双击没反应 | Windows Defender 把它删了 —— 见 §3.2 |

## 9. 坑清单（这一路踩过的，按疼的程度排序）

1. **`board.py -f` 并发覆盖**：它固定上传到 `/tmp/_s.sh`，两个人同时用会互相截断脚本
   → 已修：改成 `/tmp/_run_<文件名>_<随机>.sh`，跑完自删。
2. **改 IP 源码不生效**：`generate_target` 不会重新复制源码，白跑 25 分钟出流。
   验证脚本 `test_ip_propagate.tcl` 只要 20 秒。
3. **百度两套 Key**：语音和文字识别是两个独立应用，OCR 返回 `error 6` 就是没建对应用。
4. **桌面服务读不到密钥**：`zynq-desktop` 没配 `EnvironmentFile`，
   而 `tts.py` 只认环境变量 ⇒ 静默退回 vosk。已修成主动读 `/etc/zynq-baidu.env`。
5. **`self.xxx` 只在业务路径里创建**：加了读它的绘制代码 ⇒ 一打开 App 就
   `AttributeError`。教训：**绘制路径和业务路径是两条路**，绘制要读的状态必须在 `__init__` 里先立好。
6. **手写每帧全屏 flush**：127ms/帧 ⇒ 17 帧/秒。改成"静态层 + 工作层 + 脏矩形 blit"后
   1~3ms/帧（脏矩形只占面板的 0.03%）。
7. **静音切句阈值太小**（0.45s）：真人说话的自然停顿被切断 ⇒ 每段单独送 ASR ⇒ 丢上下文 ⇒
   长句识别差。调到 0.85s + 定稿段带 0.35s 上下文。
8. **百度对纯静音会"幻觉"出文字**（凭空多出"我知道。"）⇒ 送 ASR 前先量 RMS，太安静就不送。
9. **`audioop` 在 Python 3.13 被移除**（PEP 594）⇒ 音频格式转换整个崩。板子上 3.8 有，
   但 PC 侧脚本别再依赖它。
10. **`poweroff` 是单向的**：板子关了只能手动上电。**调试期间一律用 `systemctl reboot`。**
11. **PowerShell 5 的 `Out-File -Encoding UTF8` 会写 BOM** ⇒ 传到 Linux 执行时报
    `$'\357\273\277echo': command not found`。写 shell 脚本要用无 BOM 的方式。
12. **Windows Defender 误删 exe**（`Trojan:Win32/Bearfoos.A!ml`），而且是在
    **启动 exe 的那一刻**触发 —— 验证 GUI 程序时不能只看"进程活着"，还要确认文件还在。
13. **`flush(box=...)` 比全屏 flush 还慢**：内部是 crop+convert+逐行 Python 循环。
    要局部刷新就用 `blit_raw`。
14. **看门狗读错文件**：`tunnel_guard.py` 读 `tunnel.err` 而 `tunnel.py` 写 `tunnel.log`
    ⇒ 一直显示 24 小时前的旧地址。
15. **板子上的旧副本**：`D:\ubuntu_iso\ui\` 里有一批 09-27 的旧副本，
    别拿它当源 —— 真正的源在板子上（或用本包的 `board_ui/`）。
