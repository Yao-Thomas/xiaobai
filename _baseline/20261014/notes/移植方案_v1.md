# 示波器移植方案（草案 v1）

> 2026-10-14　目标：**音频 + 原示波器 + 他的双通道示波器，三者共存，一个都不删**
> 数据来源：逐 PACKAGE_PIN 精确核对（我们 `system.xdc` 88 端口 vs 他 `scope_dual.xdc` 81 端口）
> 配套：`移植影响评估.md`

---

## 一、★ 核心结论：**冲突只有 1 根引脚**

| 项 | 结论 |
|---|---|
| **音频 I2S（6 根）** | ✅ **完全不受影响** —— 他一根都没用，全部空着 |
| **LCD（29 根）** | ✅ 完全一致，无冲突 |
| **以太网（14 根）** | ✅ 完全一致，无冲突 |
| **PS I2C（触摸 + ES8388 配置）** | ✅ 不受影响（他用的是 PL 侧 AXI IIC） |
| **摄像头 cmos（11 根）** | ⚠️ 被他拿去当 ADC —— 但**我们本来就没用** ✓ |
| **can0 / uart1（4 根）** | ⚠️ 被他拿去当 gpio0 —— 我们没用 ✓ |
| **★ V15（1 根）** | ❌ **唯一真冲突**：我们 `gpio0_tri_io[7]` vs 他 `adc1_data[0]` |
| **地址 0x43CC0000** | ❌ 他的 scope_dual_axi 撞我们的 scope_cap_axi |

**⇒ 结论：只要解决「V15 一根引脚」+「一个地址」，就能三者共存。**

## 二、引脚分配方案

### 2.1 保留不动的（我们的）
```
LCD      29 根：lcd_clk P19 / lcd_de U20 / lcd_hs N18 / lcd_vs T20
                lcd_bl[0] M20（★背光）/ lcd_rst L17（★复位）
                lcd_rgb_tri_io[0..23]
音频     6 根：aud_adcdat M17 / aud_adclrc L20 / aud_bclk M18
                aud_dacdat G17 / aud_daclrc G18 / aud_mclk E19
以太网   14 根：mdio_mdc F20 / mdio_mdio_io F19
                rgmii_rxc K17 / rx_ctl E17 / rd[0..3] B19 A20 H17 H16
                rgmii_txc B20 / tx_ctl K18 / td[0..3] D18 C20 D19 D20
PL I2C1  2 根：i2c1_scl_io R19 / i2c1_sda_io P20（他也有，一致）
```

### 2.2 让给他做 ADC 的（我们没用）
```
摄像头 cmos 11 根 → ADC：V13 W13 U15 U14 V12 U13 Y14 W14 R14 + (另外几根)
can0        2 根 → J14 给 gpio0[7]，L16 空出
uart1       2 根 → K14 给 gpio0[10]，M15 空出
i2c0 / i2c2 / tmds(HDMI) / pl_led → 全部空出
```

### 2.3 ★ V15 那一根怎么解决（两个选项）

| 选项 | 做法 | 影响 | 推荐度 |
|---|---|---|---|
| **B1** | 把 `adc1_data[0]` 从 V15 挪到另一个空脚 | 只动他的 ADC 低位一根，时序不受影响 | ⭐⭐⭐⭐⭐ |
| **B2** | 把我们的 `gpio0_tri_io[7]` 从 V15 挪走 | 要动我们的 BD 接线，风险高 | ⭐⭐ |

**⇒ 推荐 B1**：ADC 数据线换一根脚完全不影响功能（10 位并行数据，哪根都是数据）。
**备用空脚候选**：从他让出的 31 根里挑（如 `L16`、`M15`、`E18/F17` i2c0、`T10/T11` i2c2、`H15/L15` pl_led、`J20/K19/G19/J18` tmds 等）

### 2.4 ⚠️ 要确认的一点
```
xdc 里 gpio0_tri_io 有 11 根，但 DT 里只有 3 个 AXI GPIO（3+2+3 = 8 位）
⇒ 需确认 gpio0[7]（V15）在我们系统里到底用没用
   · 如果没用 → 直接让给 ADC，连挪都不用挪
   · 如果用了 → 走 B1
```

## 三、★ 地址冲突方案

```
他：scope_dual_axi @ 0x43CC0000 (64K)
我们：scope_cap_axi @ 0x43CC0000  ← 撞
```

| 选项 | 做法 | 说明 |
|---|---|---|
| **A1** | 把**示波器搬到新地址**（如 0x43D00000） | 需改他的 `scope_dual.py` 基地址；我们的不动 |
| **A2** | 把**我们的 scope_cap 搬走** | 需改我们的 `scope.py` + apps_scope.py |
| **A3** | 两个都搬到连续地址 | 最干净，但要改两边 |

**⇒ 推荐 A1**（他的代码只有一处基地址常量，改动最小；我们的系统一行不动）

## 四、实施阶段（每步都备份 + 验证 + 可回滚）

### 阶段 2：PC 侧（不碰板子）
```
2.1 读他的 utilization.rpt / CNN_RESOURCE_BUDGET.md → 确认资源够
      现有：我们的设计 + scope_cap + gpu2d + CNN
      新增：他的 scope_dual_core（2 通道 × 4096 × 10 位 双 bank）
      ★ 必须先算清楚够不够，ZYNQ7020 只有 53200 LUT / 140 BRAM / 220 DSP
2.2 在他的 build_scope_dual.tcl 基础上改：
      · 基地址 0x43CC0000 → 新地址
      · adc1_data[0] V15 → 新空脚
      · 保留我们 BD 里的所有 IP
2.3 出流（用一个独立的新 BD，不动我们的 system.bd）
2.4 用他的 check_adc_post_route.tcl 检查 ADC 时序
```

### 阶段 3：上板（小步走）
```
3.1 【只装设备树补丁，不动 PL】← 安全验证第一步
      用 fdtput 把 9 个节点标 disabled：
        /amba_pl/clk_wiz@43c80000   ← 他 panic 就出在这
        /amba_pl/v_tc@43c90000
        /amba_pl/v_frmbuf_wr@43c40000
        /amba_pl/v_frmbuf_rd@43ca0000
        /amba_pl/i2c@41600000（+ ov5640@3c）
        /amba_pl/drm_pl_disp_hdmi
        /amba_pl/atk_hdmi_drm
        /amba_pl/vcap_dvp
      ★ 但我们的新 PL 里这些 IP 还在！⇒ 可能不用禁用，需逐条核对
      ★ 验证：能启动 + 屏正常 + 触摸正常 + 音频正常 + 原示波器正常
3.2 【JTAG 烧新 bitstream 验证 PL】
      不写 SD 卡、不重启、随时换回
      验证：读 0x43CC0034 得新版魔数、ADC 能采到数
3.3 【PS 侧代码】推新文件（scope_dual.py / scope_processing.py / scope_model.py /
      apps_scope_dual.py / libscopedual.so），桌面加入口
      ★ 不动我们原有的 apps_scope.py / scope.py / libscope.so
3.4 【解决那两个遗留问题】
      · 包络只填 95/1008 列（掉帧 + CPU 根因）
      · 标定
```

## 五、★ 备份纪律（每步执行）

```
① 动手前先备份将被改动的文件，带时间戳
    板端：/mnt/boot/*.bak_<动作>_<时间戳>
    PC 端：D:\ubuntu_iso\_baseline\<日期>\
② 双份：板子上 + PC 上各存一份
③ 一次只改一个变量
④ 每步立即验证四项硬指标：
     □ 能正常启动（不 panic、不黑屏）
     □ 屏正常（fb0=1024x600、LCD ID 读到值）
     □ 触摸正常（i2c-2 有 0x14、event1=Goodix）
     □ 原有功能在（音频 / 原示波器 / GPU / agent）
     + APP ERROR = 0
⑤ 不过就回滚
⑥ 每步记录：改了什么、md5 前后、验证结果
```
