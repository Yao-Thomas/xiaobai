## ★ 步骤 2：只打 dtb 补丁（**不动 PL**）—— 最安全的第一步

**★ 原理**：新 PL 如果删了某些 IP，而 dtb 还引用它们 → 内核 probe 不存在的寄存器 → 总线 abort → **panic 黑屏**（他踩过这个坑）。
**★ 但这一步 PL 还是老的，所以禁掉这些节点无害** → 用来验证补丁本身安全。

```
□ 2.1 备份当前 dtb
      板端: cp /mnt/boot/system.dtb /mnt/boot/system.dtb.bak_step2_<时间戳>
      PC 端: 下载一份到 _baseline\20261014\board_boot\
□ 2.2 用 make_dtb_patch.py 生成补丁后的 dtb（选 keep 或 trim 模式）
□ 2.3 ★ 5 道安全闸全过（脚本自动）：
      · 闸1: LCD/音频/触摸的 13 个节点必须还在
      · 闸2: 禁用的是否整组（不许留悬空 phandle）
      · 闸3: 节点引用链闭合
      · 闸4: ★ chosen/bootargs 里的 mem=992M 必须还在（CNN 的 POOL_BASE=0x3E000000 依赖它！）
      · 闸5: 反编译后逐节点比对
□ 2.4 写进 /mnt/boot/system.dtb（新的放进去，老的备份留着）
□ 2.5 sync + 重启
□ 2.6 ★ 验证四项硬指标（能启动 = 补丁安全）
      ★ 不过 → 立刻用备份的 dtb 还原 + 重启
```

**回滚点**：`cp /mnt/boot/system.dtb.bak_step2_* /mnt/boot/system.dtb && reboot`

## ★ 步骤 4：只读探测新 PL（**不写任何东西**）

```
□ 4.1 读他的示波器寄存器，确认 PL 活着
      0x43CF0034 = VERSION  → 应 0x53435033 (SCP3)
      0x43CF0038 = CAPS     → 应 0x020A1000
      0x43CF003C = RATE     → 应 0x01312D00 (20MHz)
      0x43CF0078 = CLKCNT   → sample_clk 计数，应该在动（证明时钟树在跑）
      0x43CF007C = TESTPAT  → 写非 0 打开内部测试波形
      0x43CF006C = LIVE     → 实时 ADC 引脚值
      0x43CF0070 = ACT      → 数据翻转次数
      0x43CF0074 = EVER     → 各位是否出现过高/低
□ 4.2 ★ 用 TESTPAT 内部测试波形验证采集通路（不需要任何外部硬件！）
      写 TESTPAT != 0 → 读 FRAMESEQ 看帧号有没有在递增
      → 读 ST_MM1/ST_MM2 看波形统计是否合理
□ 4.3 ★ 此时可以复现并验证「95/1008 列」那个 bug
      读 ENV_PTR=0 → 连读 1008 次 ENV_DATA → 数非零列数（应该只有 95）
      ⇒ 这正是他文档里那个 bug，PL 层就能复现
```
