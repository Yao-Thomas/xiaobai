## 1. ★★ 最关键的一条：输入几何锁定 28×28，不是 32×32

### 冲突在哪里

| 出处 | 说法 |
|---|---|
| `07_接口约定单.md` 接口① 示例 | `"input_shape": [1, 32, 32]`，但同段 `fc` 写 `"in": 400` |
| `07_接口约定单.md` 接口② | `"input_shape": [1, 32, 32]` |
| `06_分工总表` 第②节 | "图尺寸（对齐 CNN 加速器，如 32×32）" |
| **上一轮 HLS 源码**（真凭实据） | `cnn_conv_pool_q.cpp`：`OH = (IH-KH+1)/P` |

### 为什么 32×32 与 `fc in=400` 自相矛盾

按 HLS 的真实公式（`P` = 池化步长 = 2，`K` = 3，无 padding）：

| 输入边长 | Conv1 输出 | Pool1 | Conv2 输出 | Pool2 | 展平 |
|---|---|---|---|---|---|
| **28** | 26×26 | 13×13 | 11×11 | **5×5** | 16×5×5 = **400** ✅ |
| 32 | 30×30 | 15×15 | 13×13 | 6×6 | 16×6×6 = **576** ❌ |

⇒ **`fc in=400` 只在输入为 28×28 时成立。** 交接包 `05_M4b_CNN方案.md`
写的也是 `输入 28×28×1 → … → Pool2 5×5×16 (=400) → FC 400→10`。
上一轮板上实测通过的 `[CNN OK] 400/400 点一致` 就是 400 这个数。

### 决策（本文件冻结）

```
★ 输入 = 1 × 28 × 28 × int8
★ Conv1 3×3 1→8  (无 pad, stride 1) + ReLU + 2×2 MaxPool → 8×13×13
★ Conv2 3×3 8→16 (无 pad, stride 1) + ReLU + 2×2 MaxPool → 16×5×5 = 400
★ FC    400 → 9
```

**理由：改输入尺寸 = 改加速器 = 改硬件 = 要重新出流。红线 2 明确禁止。**
28×28 的代价只是 STFT 少 4 个频点/帧，收益是**PL 侧一行都不用改**。

**★ 需要主線融合负责人确认一句："数据集的 `input_shape` 用 28×28，可以吗？"**
（不影响他任何工作，只是把 `07` 文档里的示意值改掉。）

## 2. ★ 输入形态：**时间×幅度密度图（wdens）**

> ★ 修订（v1.1）：`07` 文档**建议**用 STFT。经实测，
> **STFT 在"示波器显示 2~5 个周期"这个工况下不可用**（一个窗内只有 0.25~0.63 个周期，
> 谐波完全糊在一起）。因此改用**时间×幅度密度图**。
> 完整推导 + 两轮对比实测见 **`docs/01_输入表示选型.md`**。
> STFT 参考实现在 `preprocess.py` 里**保留**，`--pp stft` 一行可切。

**参考实现：`src/common/preprocess.py`**
（含 numpy 与纯 Python 两条路径，已断言逐点一致；板端可直接拷这个文件，无第三方依赖）。

```
输入 : 4096 个 8 位样本（示波器 capture_once() 的 samples），uint8 0~255
输出 : 28×28 uint8

 28 列 = 时间：4096 个采样点均分（每列 146 点，最后一列吃掉余数）
 28 行 = 幅度：8 位码值 0~255 均分；★ 行 0 = 顶部 = 高电平（与示波器屏幕方向一致）
 格值 : 该列内落在该幅度档的采样点【个数】
        → 除以该列总点数（= 列内密度）
        → 开平方（方差稳定化：让弱轨迹/孤立亮点也看得见）
        → 按【本样本自身最大值】归一化，四舍五入到 0~255
 送硬件: int8 = u8 - 128        ← ★ 唯一的一次变换，板端也要做这一步
```

### 为什么这个表示在两种工况下都有判别力

| 工况 | 表现 |
|---|---|
| **少周期 K=4**（示波器显示工况） | 每列只覆盖 1/7 个周期，格点**直接勾出波形形状** ⇒ 正弦/方波/三角/锯齿肉眼可分 |
| **多周期 K=64** | 每列覆盖 2.3 个周期，格值退化为**该列的幅度分布**：正弦=反正弦分布 / 三角=均匀 / 方波=双尖峰 / 噪声=高斯 ⇒ 依然可分；**占空比异常直接表现为上下两轨亮度不对称** |

### 实测对比（同种子、同超参、同一份原始缓冲，只换预处理）

| 表示 | 9 类 test_acc | 8 类 test_acc |
|---|---|---|
| **wdens（交付）** | 0.7960 | **0.9265** |
| stft | **0.8147** | 0.9055 |

准确率互有胜负、差距 2% 量级；按**鲁棒性（覆盖全 K 区间）、板端成本
（不用在 A9 上跑 28 次 512 点 FFT）、可解释性（演示时观众直接看到波形）**
选 wdens。

### （保留）STFT 的参数，供 `--pp stft` 使用

```
NFFT = 512, HOP = 132（末帧右对齐到 4096-512，保证覆盖整段缓冲）
Hann 窗；|rfft| ；频率轴 bin 1..256 对数分 28 行（每行取频段最大值）
相对本样本峰值固定 60 dB 动态范围；round(v×255)
```

### 训练集覆盖的工况（域随机化，不是教科书 demo）

> 交接包的提醒：**"准确率不是难点，难点是怎么让它不只是教科书 demo"**。这条直接落实在这里。

| 维度 | 训练覆盖范围 |
|---|---|
| 缓冲区内周期数 K | **4 ~ 64**（对数均匀）；另用 K=2~5 的"示波器显示工况"做鲁棒性验证 |
| 幅度 | 45~118 LSB（10% 概率 18~45 LSB 的小信号） |
| 直流偏置 | ±6 LSB |
| 通道增益误差 | 0.92 ~ 1.08 |
| 高斯噪声 | σ = 0.4 ~ 3.2 LSB（**不是无噪声**） |
| 采样抖动 | 0 ~ 0.004 周期 rms |
| 8 位量化抖动 | 0 ~ 0.5 LSB |

## 4. ★★ requant 与 MFQ：一个必须说清的技术事实

### 4.1 结论先说

```
公式不变：  out = relu/sat((acc × MFQ) >> 16)          ← 上一轮方案，完全沿用
MFQ 取值：  本项目【逐层】标定（conv1 / conv2 / fc 各一个）
硬件改动：  ★ 零。MFQ 在 HLS 里本来就是 s_axilite 寄存器
```

### 4.2 依据（请主线融合负责人核对一遍）

`源码/hls/cnn_conv_pool_q.cpp`：

```cpp
void cnn_conv_pool_q(d8* img, d8* w, d8* out,
                     int IH, int IW, int IN_CH, int OUT_CH, int KH, int KW, int P, int MFQ){
    ...
    #pragma HLS INTERFACE s_axilite port=MFQ
    ...
    s32 q = (s32)((acc * MFQ) >> 16);   // requant
```

`MFQ` 是一个**每次调用都可以传不同值的寄存器**，不是烧进 bitstream 的常量。
上一轮的 `MFQ=119` 是**主机侧为那个 MNIST 模型校准出来的值**
（证据：`源码/tools/verify_uniform_m.py` 里在试 `MFQ ∈ {119,115,120,108}` 找分类正确的那一个）。

### 4.3 为什么新模型不能直接用 119

MFQ 的作用是 `y_int8 = acc × MFQ / 65536`。要让 int8 输出**用满** [0,127] 而不饱和：

```
需要的 MFQ ≈ 127 × 65536 / max|acc|
```

`max|acc|` 取决于该层有多少次累加（Conv1 只有 9 次，FC 有 400 次），
**三层差 40 倍以上**。一个统一 MFQ 必然让某些层的权重被压到只剩 1~2 个量化级，
精度损失不可接受。⇒ 逐层 MFQ 是**正确的做法**，而且**硬件早就支持**。

### 4.4 溢出（★ 必须遵守的约束）

```cpp
s32 q = (s32)((acc * MFQ) >> 16);   // ap_int<32>，溢出会回绕
```

⇒ 约束 **`max|acc| × MFQ < 2³¹`**。
本项目在训练/导出时**逐层实测 `max|acc|` 并检查余量**，写进 `model_spec.json` 的
`requant.overflow_rule`；并且 `reference_out.bin` 的生成代码里
**逐位模拟了 int32 回绕**，所以哪怕真的溢出，参考输出与真硬件也一致。

### 4.5 兼容回退（如果板端只支持一个 MFQ）

导出时**同时产出**一个 `quantized_model_uniform_mfq/`（全部层用同一个 MFQ），
并给出它的实测测试集准确率。若与逐层版差距可接受，主线融合负责人可以直接用这个版本，
**接口 schema 一行都不用改**。两个版本的差异只在 `model_spec.json` 的 `requant` 字段。

**★ 本模型的实测对比（说明"必须逐层"不是理论洁癖）**：

| 版本 | 测试集准确率 |
|---|---|
| **逐层 MFQ（交付）** | **0.9590** |
| 统一 MFQ = 119 | 0.5540 |

统一 MFQ 直接掉到 0.55 —— 因为 conv1 只有 9 次累加、FC 有 400 次，
`acc` 峰值差 40 倍以上，一个统一乘子必然让某些层的权重被压到只剩 1~2 个量化级。

### 4.6 `model_spec.json` 里怎么写（不破坏必需字段）

```json
"requant": {
  "formula": "out = relu/sat((acc * MFQ) >> 16)",
  "shift": 16,
  "MFQ": 1390,                                   ← 必需字段保留（= 逐层版 fc 的值）
  "MFQ_per_layer": {"conv1": 201, "conv2": 371, "fc": 1390}   ← 新增可选字段
}
```

板端读法：**有 `MFQ_per_layer` 就用它；没有就用 `MFQ`。** 向后兼容，不会读坏。

## 5. 接口 ②：数据集格式（本节即"双方写死"的版本）

目录结构与 `07_接口约定单.md` **完全一致**，只增加两个**在 `meta.json` 里显式声明**的扩展。

```
dataset/
├─ meta.json
├─ train/  00000.npy  00000.json  ...       # .npy = (1,28,28) uint8
├─ val/    ...
├─ test/   ...
├─ raw/    raw_train.npy  raw_val.npy  raw_test.npy     【扩展】
└─ packed/ img_train.npy label_train.npy meta_train.json 【扩展】
```

| 扩展 | 内容 | 为什么加 |
|---|---|---|
| `raw/` | `(N,4096)` uint8 原始采集缓冲 | ① 示波器负责人可**逐条核对**他采的数据 ② 预处理参数要改时**不用重采** |
| `packed/` | 与 `train/` 逐样本文件等价，但打包成一个 `.npy` | 2 万条样本 = 4 万个文件，逐个读会让 DataLoader 慢 10 倍以上 |

**★ 这两项在 `meta.json` 的 `extensions` 字段里写明，不影响任何按规范读 `meta.json`/`train/` 的程序。**

### 单个样本

`00000.npy`：`(1, 28, 28)` **uint8**（接口②允许 float32 或 uint8；本项目统一 uint8，
因为它就是 8 位 ADC 的码值，也是加速器输入变换 `-128` 的直接来源）。

`00000.json`：
```json
{
  "label": "square",
  "anomaly": null,
  "base_waveform": "square",
  "class_index": 1,
  "freq_hz": 15258.79,
  "cycles_in_capture": 12.5,
  "amp": 96,
  "duty": 0.5,
  "noise_level": 1.42,
  "dec": 64,
  "fs_hz": 312500.0,
  "dc_offset": -2.1,
  "gain": 1.03,
  "dds_params": {"waveform": 1, "freq_word": 32768000, "amp": 96, "dec": 64, "phase0": 0.37}
}
```

**★ `dds_params` 是标签可追溯性的关键**：DDS 参数即标签，100% 精确、可无限重放。

### ★ 类别表（冻结，禁止改顺序 —— 模型输出下标 = 本表下标）

**交付使用 8 类**：

| idx | label | 中文 | 说明 |
|---|---|---|---|
| 0 | `sine` | 正弦 | |
| 1 | `square` | 方波 | 干净方波占空比 0.49~0.51 |
| 2 | `triangle` | 三角 | |
| 3 | `sawtooth` | 锯齿 | |
| 4 | `noise` | 噪声 | 无周期结构 |
| 5 | `clipping` | 削顶 | **含轻度削顶**（保留 55%~90% 峰值） |
| 6 | `signal_loss` | 丢信号 | 平线 or 强衰减段 |
| 7 | `duty_abnormal` | 占空比异常 | 方波底波形，duty 0.12~0.36 / 0.64~0.88（15% 为轻度 0.40~0.46 / 0.54~0.60） |

**★ 为什么没有 `glitch`（毛刺）** —— 已实测，不是遗漏：

- 二分类【毛刺 vs 干净波形】只能收敛到多数类（`test_acc = 0.8000 =` 正例比例，
  毛刺召回 **0.000**）；
- 一个 2~10 采样点的毛刺映射到 28×28 密度图后**只改变 2~5 个像素（共 784 个）**，
  低于样本间纹理差异 ⇒ **在 4096 点采集 + 28×28 画布上不可分**。
- 这与团队分工一致：`06_分工总表` 里示波器负责人第 3 项写着
  "**毛刺是 ns 级的，CPU 采样根本采不到 —— 只有 FPGA 能在信号源头抓**"。

**9 类版本可一行切换**：`dataset_gen.py --with-glitch`。
`dds_sim.CLASSES_REQUIRING_PL` 明确标注了它归 PL 负责。
完整证据见 `docs/01_输入表示选型.md §4`。

**异常样本的底波形**（正弦/方波/三角/锯齿）记在 `base_waveform` 字段里，
所以异常类样本**不丢失底波形信息**，agent 可以两个维度都用。

### 数据增强（训练时在线做，不进数据集文件）

**★ 必须按输入表示选对应的几何变换** —— 两种表示的行语义完全不同：

| 表示 | 行语义 | 幅度轴（行）增强 | 时间轴（列）增强 |
|---|---|---|---|
| `wdens`（交付） | 行 = **幅度** | **以中心行做仿射（缩放 0.82~1.22 + 平移 ±2.5 行），且必须用【最大值重采样】** | 循环平移 ±3 列 |
| `stft` | 行 = **对数频率** | 行循环平移 ±4（reflect 边界） | 循环平移 ±3 列 |

**两个坑（都会把"毛刺"这类细微信号擦掉，第一版都踩了）**：
1. 在 `wdens` 上做**行循环平移**是错的（会把高幅度折到底部）；
2. 幅度轴仿射若用**最近邻重采样**，会把某些源行整行丢掉 ——
   而毛刺在密度图里常常只有 1 个像素 ⇒ 等于把毛刺擦掉。**必须用最大值重采样**。

加性噪声控制在 **σ ≤ 3 LSB**（太强会淹没细微信号）。

**★ 不做水平（时间轴）翻转**：锯齿波翻转后等价于另一种波形，会制造错误标签。

## 9. ★ 给主线融合负责人的三句话

1. **几何锁定 28×28**，`07` 文档里的 32×32 是示意值，与 `fc in=400` 矛盾 —— 我按 28×28 做了，你不用改任何硬件。
2. **MFQ 我用逐层（201/371/1390）**，因为它是寄存器不是常量；接口 schema 加了一个**可选**字段 `MFQ_per_layer`，你不读它就等于没变。若你的 PS 代码只想传一个值，用 `quantized_model_uniform_mfq/`（准确率 0.554，差很多，不建议）。
3. **`reference_in.bin` + `reference_out.bin` 一定有**（64 组），并且我这边已经用"HLS 循环的纯整数复刻"产生了输出，连 `ap_int<32>` 的溢出回绕都模拟了 —— 你按 `[CNN OK] 8/8 点一致` 那套比对就行。
