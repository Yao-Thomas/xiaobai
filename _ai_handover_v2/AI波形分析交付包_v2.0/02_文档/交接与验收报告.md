## 3. 联调三步（10 分钟）

```bash
# ① 在 PC/服务器上启动（日志会打印"板端填 http://<IP>:8000"）
python -m wave_ai.serve --port 8000 --model runs/v2_full/model_bundle.pt

# ② 健康检查
curl http://<IP>:8000/health

# ③ 拿夹具测一条，确认板端能解析
curl -X POST http://<IP>:8000/waveform/analyze \
     -H 'Content-Type: application/json' -d @deliverables/fixtures/test_wave_square_0.json
```

**板端请求里必须带对的字段**：

| 字段 | 说明 |
|---|---|
| `samples` | 4096 个 0~1023 整数 |
| `dec` | **必须是当前真实抽取倍率**（K/频率/时间类指标全依赖它；填错掉约 10 个点） |
| `local_cnn` | 端侧 8 类结果；没有也能跑（94.5%） |

**超时建议**：局域网 1.5 s，云端 8 s，连不上立即回退端侧。

## 5. 需要你们配合的三件事

1. **采数据**（最高优先级）：按 `docs/数据采集清单.md`，优先 `square / sine / duty_abnormal / glitch / ringing`。
   采完跑 `python -m wave_ai.finetune --real <目录>`，模型会立刻贴合你们的硬件。
2. **告诉我 `dec` 的典型取值**：演示时用 dec=10 还是 20/40？这决定质量指标能测到哪几项
   （dec=10、1 kHz 只有 2 个周期，抖动/占空比稳定度会返回 null）。
3. **确认端侧 8 类的实际输出**：如果 PL CNN 重训后类别名/顺序有变，改 `wave_ai/config.py` 的 `CLASSES_8` 一处即可。

## 6. 风险与局限（提前说清，避免验收时扯皮）

| 风险 | 影响 | 缓解 |
|---|---|---|
| 训练数据是仿真 | 真实板卡上可能掉 2~5 个点 | 真实数据微调（已备好脚本）；困难域 83.3% 作为下界参考 |
| `square ↔ duty_abnormal` 轻度偏差混淆 | square P=0.832 | 用板端硬件占空比测量兜底（误差 ≤0.3%） |
| dec=10、1 kHz 只有 2 个周期 | 抖动/占空比稳定度返回 null | 演示"完整质量报告"时把 dec 调到 20~40 |
| glitch 的 ns 级毛刺采不到 | 该类只能看到 1~6 µs 的尖峰 | 按分工归 PL 硬件检测器 |
| 未知异常对"两类混合"检出率 28% | 演示"识未知"需挑形态 | 用"双频+削顶+漂移"三合一这类多规则同时命中的例子 |
| 无 GPU 环境 | 训练 11 min/次（CPU） | 已是最小可复现配置；换 GPU 机可直接跑同一脚本 |
